# Order Data Model

## Order

An order represents a customer's request to purchase one or more products.

## Order Fields

| Field | Description |
|---|---|
| orderId | Unique order identifier generated by the backend |
| customerId | Customer identifier |
| items | Products and quantities in the order |
| status | Current order processing state |
| createdAt | Order creation timestamp |

## Example Order

```json
{
  "orderId": "ORD-12345",
  "customerId": "CUST-001",
  "items": [
    {
      "productId": "PROD-001",
      "quantity": 2
    }
  ],
  "status": "PENDING",
  "createdAt": "2026-09-25T10:30:00Z"
}

## Order Statuses
PENDING
PROCESSING
COMPLETED
FAILED
PENDING

The order was accepted and stored, but asynchronous processing has not completed.

## PROCESSING

The order processor is currently processing the order.

## COMPLETED

Order processing completed successfully.

## FAILED

Order processing failed after the processing workflow determined that the order could not be completed.

## API Request

{
  "customerId": "CUST-001",
  "items": [
    {
      "productId": "PROD-001",
      "quantity": 2
    }
  ]
}

The client does not provide orderId, status, or createdAt.

These are generated/managed by the backend.

## API Response

{
  "orderId": "ORD-12345",
  "status": "PENDING",
  "message": "Order accepted"
}

The API returns after the order has been accepted and stored. It does not wait for asynchronous processing to finish.

## OrderCreated Event

{
  "eventType": "OrderCreated",
  "orderId": "ORD-12345",
  "customerId": "CUST-001",
  "createdAt": "2026-09-25T10:30:00Z"
}

The event is published after the order is stored successfully.

## API Validation Rules

### customerId

- Required
- Must be a non-empty string

### items

- Required
- Must be an array
- Must contain at least one item

### Order Item

- `productId` is required
- `productId` must be a non-empty string
- `quantity` is required
- `quantity` must be an integer
- `quantity` must be greater than 0

## Validation Failure

Invalid requests are rejected before the order is written to DynamoDB or an `OrderCreated` event is published.

Example response:

```json
{
  "error": "ValidationError",
  "message": "customerId is required"
}
